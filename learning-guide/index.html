FOURTH-YEAR PROJECT LEARNING GUIDE

AI-Powered Market Intelligence & Document Analysis using RAG + HPC on AWS

This guide matches the separate cleaned local project; it does not claim that AWS is deployed.

1. What are we building?

A web tool that reads market reports, finds relevant evidence, computes relationships between documents, and helps researchers interpret those relationships.

Input: PDF/DOCX/CSV reports. Output: cited passages, similarity scores, clusters, honest performance measurements.

Document similarity does not mean future market growth. We must not present a cluster as a prediction.

2. Actual local architecture

Uploaded reports→Text + source locations→Saved chunks

From there, the user can ask questions or perform numerical analysis:

Chunks→TF-IDF retrieval→Sources / optional local LLM
Chunks→Document feature vectors→Sequential / real MPI→Results

Why are there two paths? Retrieval answers evidence questions. The numerical path computes similarities and clusters. It is not necessary to run HPC for every question.

3. How document question-answering works

  1. Validate PDF, DOCX or CSV.
  2. Extract text while saving page or row location.
  3. Divide into chunks to find relevant passages.
  4. Use TF-IDF to retrieve relevant chunks in the default local mode.
  5. Show sources. If Ollama is configured, send the evidence to the local LLM for an answer.

RAG: Retrieval-Augmented Generation. Full RAG needs both retrieval and an actual generation model. With Ollama turned off, this app uses evidence retrieval without generation.

Optional: use a downloaded local sentence-transformer for neural embeddings. A hashing or TF-IDF representation is not the same as a transformer embedding.

4. Why HPC and how MPI works

HPC: High-Performance Computing. MPI: Message Passing Interface, which coordinates independently executing processes.

Comparing N documents with one another requires roughly N² comparisons. The dimension d of each vector also contributes to cost, approximately O(N²d).

Input vectors→MPI rank 0MPI rank 1MPI rank 2→Gather matches

Each rank computes its own range of document rows. That is genuine MPI only when ranks are launched by mpiexec and communicate using mpi4py.

Distributed K-Means is more collaborative: each rank assigns its local points, then Allreduce combines local cluster sums/counts and every rank receives the updated centroids.

Ubuntu on Windows? WSL2 allows a Linux MPI runtime without replacing Windows. The final AWS cluster uses a similar Linux/MPI setup.

5. How to prove it

Run the same dataset with sequential code and with real MPI ranks. Check both answers match. Then compare execution times. Process launch and communication can make small jobs slower.

7. What changes for AWS?

Today this package is local-first. For final deployment: use S3 for data; Bedrock for retrieval/generation; deploy a secured containerized web app; use ParallelCluster/Slurm to schedule MPI jobs on EC2; send results back through managed storage.

AWS deployment, budgets, permissions and public security are separate tasks. This learning website performs no cloud actions.

8. Viva practice

Why MPI instead of ordinary Python?

MPI communicates between independently executing processes and can scale across machines. It is helpful for large partitionable mathematical workloads when overhead is justified.

Is TF-IDF the same as neural embeddings?

No. TF-IDF uses term statistics; an optional local sentence-transformer creates contextual neural representations.

How do we know clustering is really distributed?

Each MPI rank computes assignments for disjoint rows; Allreduce aggregates sufficient statistics to update global centroids; actual rank logs and correctness tests confirm the result.

Did we deploy on AWS?

Not in this local baseline. AWS provisioning and runtime verification are still required for final submission.

Is speedup guaranteed?

No. The workload must outweigh process launch and communication overhead; negative speedup can be reported honestly.
